# StegoBox

Экспериментальное приложение на Java 21 + Swing, демонстрирующее **LSB-стеганографию** в сочетании с **AES-256** шифрованием. Позволяет спрятать произвольный текст внутрь PNG/BMP-изображения так, что картинка открывается любым просмотрщиком как обычно, а извлечь текст можно только зная пароль.

---

## Возможности

- **Скрытие текста в изображении** методом LSB (Least Significant Bit) — младшие биты каналов R, G, B заменяются битами зашифрованного сообщения.
- **Шифрование AES-256/GCM** с ключом, производным от пароля через PBKDF2-HMAC-SHA256 (120 000 итераций).
- **Извлечение и расшифровка** текста из изображения по паролю.
- **Автоматическое сохранение** результата в ту же папку, где лежит исходник, с суффиксом `_stego.png`.
- **Проверка ёмкости** — если текста слишком много для выбранной картинки, приложение сообщит об этом до начала работы.
- **Современный UI** на [FlatLaf](https://www.formdev.com/flatlaf/) (светлая тема).
- **Асинхронная обработка** — тяжёлые операции выполняются в `SwingWorker`, UI не подвисает.

## Использование

### Скрыть текст

1. Нажмите **«Обзор...»** и выберите PNG или BMP-изображение.
2. Введите текст в центральное поле.
3. Введите пароль.
4. Нажмите **«Скрыть текст в изображении»**.
5. Рядом с исходным файлом появится `<имя>_stego.png` — в нём уже спрятан зашифрованный текст.

### Извлечь текст

1. Нажмите **«Обзор...»** и выберите PNG-файл со скрытым текстом.
2. Введите тот же пароль.
3. Нажмите **«Извлечь текст из изображения»**.
4. Извлечённый текст появится в центральном поле.

## Как это работает

### LSB-стеганография

Каждый пиксель PNG/BMP содержит три цветовых канала — **R**, **G**, **B** — по 8 бит каждый. Младший бит каждого канала почти не влияет на восприятие цвета: изменение на единицу (например, `0x7A` → `0x7B`) визуально незаметно.

Мы заменяем младшие биты каналов R, G, B последовательно (слева-направо, сверху-вниз) битами полезной нагрузки. В одном пикселе помещается **3 бита**, значит изображение размером `W × H` может хранить:

```
capacity_bytes = (W × H × 3) / 8
```

Например, картинка 1000×1000 может вместить около **366 КБ** данных.

### Шифрование

Перед встраиванием текст шифруется:

```
password ──PBKDF2-HMAC-SHA256──▶ 256-битный ключ
                                     │
plaintext ──AES-256/GCM──▶ salt ‖ IV ‖ ciphertext ‖ tag
```

- **PBKDF2** с 120 000 итераций делает перебор паролей медленным.
- **GCM** обеспечивает и конфиденциальность, и аутентификацию: неверный пароль или изменение пикселей приводят к ошибке расшифровки.
- **Salt (16 байт)** и **IV (12 байт)** генерируются случайно при каждом шифровании и сохраняются рядом с шифротекстом — это значит, что один и тот же текст с одним и тем же паролем каждый раз даёт разные байты.

### Формат скрытых данных

```
[4 байта: длина payload] [payload]
payload = [16 байт salt] [12 байт IV] [шифротекст + 16 байт GCM-тега]
```

Заголовок с длиной позволяет при извлечении понять, сколько байт читать из младших битов.

## Важные замечания

### Почему только PNG и BMP?

LSB-стеганография требует **сжатия без потерь**. JPEG использует дискретное косинусное преобразование и отбрасывает «незначительные» детали — а именно в них мы и прячем данные. После сохранения в JPEG скрытая информация будет уничтожена.

Поэтому приложение:
- **Принимает** PNG и BMP.
- **Всегда сохраняет** результат в PNG, даже если исходник был BMP.

### Альфа-канал

При загрузке изображение конвертируется в `BufferedImage.TYPE_INT_RGB`. Прозрачность (если она была в исходном PNG) отбрасывается. Это сделано намеренно: альфа-канал часто не отображается просмотрщиками, и скрывать в нём данные — плохая идея.

### Ёмкость

Реальная вместимость ограничена размером текста **после шифрования**:

```
overhead = 4 (длина) + 16 (salt) + 12 (IV) + 16 (GCM-тег) = 48 байт
```

Для русского текста в UTF-8 каждый символ обычно занимает 1–2 байта. Изображение 500×500 вмещает ~93 КБ — этого хватит на десятки тысяч символов.

### Безопасность

- Шифрование **обязательно** — без пароля приложение не работает.
- Пароль нигде не сохраняется и не логируется. После использования `char[]` затирается нулями.
- Если злоумышленник знает, что в картинке есть LSB-стеганография, он может обнаружить сам факт наличия данных (по статистике младших битов), но **без пароля прочитать их не сможет**.
- Метод **не устойчив** к пересжатию, кадрированию, масштабированию и любым другим трансформациям картинки.

## Ограничения и идеи для развития

Что **не** реализовано (и почему):

- **Устойчивость к сжатию/масштабированию.** Требует других методов (DCT, DWT) и сильно сложнее.
- **Скрытие файлов, а не только текста.** Технически тривиально (payload — просто байты), но текущий UI заточен под текст.
- **Разные темы FlatLaf на выбор.** Можно добавить переключатель светлая/тёмная.
- **Прогресс-бар для больших изображений.** Сейчас есть только статус-строка.
- **Поддержка других алгоритмов шифрования.** AES-GCM — разумный выбор по умолчанию.
